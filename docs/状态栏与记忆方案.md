# 后置状态栏与分层记忆方案

## 目标

让下一轮准确理解“此刻在哪里、谁在场、刚刚发生什么、什么必须长期记住”。沿用示例的中文栏目、人物卡、8/5 分层和完整后置展示，去掉自相矛盾的叙事指令、重复约束和无法执行的配置开关。

当前使用 DeepSeek V4.1 Flash，唯一模型 ID 为 deepseek-flash。故事、角色与世界书生成共用同一入口。旧供应商配置仅提取 DeepSeek 自己的 Key，不能把其他供应商 Key 误传给 DeepSeek。

叙事预设固定为当前代码版本，玩家界面不提供查看和编辑功能；浏览器历史自定义提示词不参与生成。世界书、角色与记忆仍可按正常玩法管理。

## 从模板修正的问题

1. 示例正文已经告别离开，状态却仍坐在咖啡馆。状态必须以本轮正文的结束时点为准。
2. “刚认识”与“长久熟悉”的关系不能凭空切换；计划与承诺不能记录成已完成事件。
3. 玩家行动既被禁止代写、又被要求大量代写，会造成冲突。这里明确：玩家给出的行动可以描述结果，新的选择、台词和心理留给玩家。
4. 每个动作固定几十字与日常对话简洁互相冲突。改成三种模式分别控制篇幅，并给结构化状态预留输出空间。
5. 用模型生成计数与强制 HTML/Python 混排容易造成格式漂移。改成模型输出 JSON，程序负责统计、排版；旧中文代码块仍可解析，任何代码都不会执行。

## 数据层

| 层 | 容量 | 记录内容 | 更新方式 |
| --- | --- | --- | --- |
| 当前状态 | 一份 | 世界、场景、人物、物品、持续效果 | 字符串字段补丁；缺失保留，明确“无”才清空语义 |
| 最近剧情 | 8 条 | 时间、地点、人物、本轮行动及结果、未决事项 | 每个成功回复仅追加一条，不覆写旧事件 |
| 长期剧情 | 5 组 | 最多 8 条原始事件组成一组 | 最近层溢出时按顺序归组，保留原始来源 |
| 核心剧情 | 不自动设限 | 身份事实、重要约定、玩家指定伏笔 | 由玩家管理，AI 无权修改或删除 |
| 角色档案 | 不自动设限 | 姓名、稳定资料、关系、最后出现位置、在场状态 | 按姓名合并，离场保留；资料变更保留历史 |
| 历史归档 | 受浏览器空间限制 | 较早的完整长期组 | 轮换归档，可查看；相关旧事可再次加入上下文 |

长期组目前采用保留原始事实的拼接归组，不进行第二次 AI 概括，避免递归总结丢失细节，也不增加额外 API 调用。代价是比有损摘要占用更多上下文与本地空间。

人物卡采用 `[姓名|年龄|身份]` 分段，后接形象、性格、衣着、鞋袜、随身物品、异常状态、关系、位置姿势等已知信息。状态 extra 记录有效道具、卡片和装备的持有人、效果、触发条件、剩余时长；没有出现新变化时整体保留。程序能保留缺失字段，但字段内部的遗漏仍需模型遵循完整更新约定，玩家可在记忆面板纠正。

## 一轮处理

1. 构造世界书、玩家设定、最新状态、全部核心及角色档案、最近8条和长期5组、相关历史归档，并加入最近16条聊天正文。
2. 请求 DeepSeek。取消、网络失败或 finish_reason 不是 stop 时不提交结果。
3. 解析正文、statusEdit 和 tableEdit。JSON 只作为数据；拒绝不正确类型与未知字段。
4. 只有状态补丁与一条有效剧情记忆同时具备时，才合并状态、追加事件、轮换层级、同步角色档案。写入失败恢复原快照。
5. 把正文和本轮数据快照一并显示。无有效元数据时正文可显示，但明确标记状态未同步，沿用上一轮；玩家可撤回重试。
6. 保存整局快照。刷新恢复同一版本的聊天和状态，撤回恢复前一轮全部数据；对话“继续说”不依赖虚构的用户消息也可撤回。

协议示例：

```text
她把深棕色笔记本递给你，问你是否愿意下周一起讨论草稿。
<statusEdit>{"location":"咖啡馆门口","characters":"[林雨晴|24岁|撰稿人]\n随身物品：钢笔\n关系：刚刚认识\n位置：站在门边","extra":"笔记本：已交给玩家"}</statusEdit>
<tableEdit>[{"action":"insert","tableId":"story_summary","data":{"time":"当日下午","location":"咖啡馆门口","characters":"玩家、林雨晴","plot":"林雨晴把草稿笔记本交给玩家，提出下周一起讨论；玩家尚未答复。","tone":"友好而期待"}}]</tableEdit>
```

## 持久化与人工管理

整局存档是恢复时的权威数据，包含世界书、玩家、消息、状态、记忆及近期撤回快照，不含 API Key。状态栏展示历史快照；手动修正修改当前数据和下次上下文，不篡改过去消息的显示。模板升级先备份，不再启动即清空。

浏览器存储有容量限制，失败时显示提示，可导出 JSON 备份。导出后仍可继续在原浏览器游玩；不要把 localStorage 当无限数据库。大量长篇剧情与每轮快照会逐步占用空间。持久化时只为最近40条消息保留撤回数据，正文和显示快照继续保留。

## 验收

- 更改供应商、模型、地址不能越过客户端及服务端检查；不会请求第三方接口或跟随重定向。
- 连续75轮事件在最近、长期及归档中仍能找到原始来源；最近最多8条，长期最多5组。
- 重复数据块或同一轮重试不产生重复记忆；AI不能删除核心事实。
- 世界书超过2000字时末尾规则仍发送；核心事实不因固定的低 Token 预算被剔除。
- 角色离场后档案仍保留；未知字段不猜测，缺失状态不清空旧值。
- 撤回第9轮可恢复第8轮的状态、8条最近记忆以及轮换前的长期层。
- 截断、取消、空正文、错误JSON、存储失败不会提交半份状态。
- 所有状态及核心内容完整展开，计数由实际数据产生，输出中的HTML按纯文字显示。

这些验证覆盖程序行为。生成内容是否符合性格、是否遗漏某件道具、是否合理推断时间，仍需要实际游玩抽查，不能用结构化存储承诺“永不遗忘”。
